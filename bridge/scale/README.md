# پل باسکول

نشان‌دهنده‌ی باسکول را می‌خواند و هر عدد را به سامانه می‌فرستد.
روی همان کامپیوتری اجرا می‌شود که کابل باسکول به آن وصل است.

## چرا لازم است

نشان‌دهنده HTTP بلد نیست؛ زبانش سریال است. این پل مترجم بین آن دو است.

**نکته‌ای که معمولاً وقت زیادی می‌گیرد:** روی ویندوز یک پورت COM را دو
برنامه همزمان نمی‌توانند باز کنند. اگر نرم‌افزار قدیمی باسکول هنوز اجرا
می‌شود، این پل پورت را باز نمی‌کند. اول آن را ببندید (و از Startup هم
حذفش کنید).

## راه‌اندازی

```bash
cd bridge/scale
npm install
cp config.example.json config.json
```

`config.json` را پر کنید:

| کلید | چیست |
|---|---|
| `url` | آدرس سامانه + `/api/weighbridge/reading` |
| `token` | از `/panel/settings/devices` ساخته می‌شود |
| `scales[].name` | نامی که اپراتور در پنل می‌بیند — «ورودی»، «خروجی» |
| `scales[].port` | `COM4` روی ویندوز، `/dev/ttyUSB0` روی لینوکس |
| `scales[].protocol` | فعلاً `raw` |
| `minGapMs` | حداقل فاصله‌ی دو ارسال؛ پیش‌فرض ۴۰۰ میلی‌ثانیه |

بعد:

```bash
npm start
```

## اول: بررسی فریم

پروتکل TEC مستند نیست، پس اول ببینیم دستگاه چه می‌فرستد:

```bash
npm run sniff
```

چیزی به سامانه فرستاده نمی‌شود؛ فقط خامِ آنچه از پورت می‌آید چاپ می‌شود:

```
HEX  53542c47532c2b202031323334352067730d0a
TEXT "ST,GS,+  12345 kg\r\n"
```

یک وزنه روی باسکول بگذارید، چند ثانیه صبر کنید، و همین خروجی را بفرستید.
هم متن لازم است هم HEX — بعضی دستگاه‌ها کاراکتر کنترلی می‌فرستند که در متن
دیده نمی‌شود ولی ساختار فریم را تعیین می‌کند.

با آن نمونه، `protocols/tec.js` نوشته می‌شود و جای `raw` را می‌گیرد.

## پارسر `raw` چه می‌کند

اولین عددی که در فریم ببیند وزن حساب می‌کند، و پرچم پایداری را از `ST`/`US`
حدس می‌زند. برای راه‌اندازی اولیه کافی است.

**برای تولید کافی نیست:** فریمی که دو عدد دارد — مثلاً وزن و شماره‌ی
باسکول — اشتباه خوانده می‌شود. تا وقتی `raw` استفاده می‌کنید، عددها را با
نشان‌دهنده مقایسه کنید.

اگر دستگاه پرچم پایداری نفرستد، `raw` همه را «پایدار» گزارش می‌کند. در آن
حالت «اجبار پایداری» را در `/panel/settings/devices` خاموش کنید — وگرنه
پلی که پرچم ندارد و سروری که پرچم می‌خواهد، هیچ وزنی ثبت نمی‌کنند.

## اجرای دائمی روی ویندوز

با [NSSM](https://nssm.cc) به سرویس تبدیلش کنید تا با ویندوز بالا بیاید:

```
nssm install NobatdehiScaleBridge "C:\Program Files\nodejs\node.exe" "C:\nobatdehi-bridge\bridge.js"
nssm set NobatdehiScaleBridge AppDirectory "C:\nobatdehi-bridge"
nssm start NobatdehiScaleBridge
```

## وقتی کار نمی‌کند

| نشانه | معمولاً یعنی |
|---|---|
| `پورت باز نشد: Access denied` | برنامه‌ی دیگری COM را گرفته |
| `پورت باز نشد: File not found` | شماره‌ی COM اشتباه است (Device Manager را ببینید) |
| باز می‌شود ولی چیزی نمی‌آید | baud rate اشتباه، یا نشان‌دهنده روی حالت ارسال نیست |
| کاراکترهای درهم | baud rate یا parity اشتباه |
| `سرور ۴۰۴ داد` | «پل باسکول» در `/panel/settings/devices` روشن نشده |
| `سرور ۴۰۱ داد` | توکن اشتباه است |
